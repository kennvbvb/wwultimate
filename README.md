# Ultimate Werewolf: Deluxe Edition — ผู้ช่วยผู้ดำเนินเกม (Google Apps Script)

เว็บแอปสำหรับ **ผู้ดำเนินเกม (Moderator)** ของบอร์ดเกม Ultimate Werewolf: Deluxe Edition
ใช้ควบคู่กับ **การ์ดจริง** ที่โต๊ะ — ระบบไม่แจกบทบาทให้ผู้เล่นและไม่แสดงภาพหรือข้อความบนการ์ดจริง
หน้าที่ของแอปคือ จัดลำดับการปลุกกลางคืน คำนวณผลการตาย ตรวจเงื่อนไขชนะ และเก็บบันทึกย้อนหลัง

> ระบบนี้อ้างอิงกติกา Deluxe Edition เท่านั้น **ไม่ปนกับ One Night Ultimate Werewolf**

---

## 1. ไฟล์ในโปรเจกต์

| ไฟล์ | หน้าที่ |
|---|---|
| `Config.gs` | ค่าคงที่ ชื่อชีต สถานะเกม ฝ่าย สถานะผู้เล่น สาเหตุการตาย ตัวเลือกกติกา |
| `RoleCatalog.gs` | นิยามบทบาททั้ง 46 ใบ (Core 34 + Wolfpack 6 + Hunting Party 6) |
| `Utils.gs` | ฟังก์ชันช่วยทั่วไป ค้นหาผู้เล่น จัดการสถานะ ตรวจเวอร์ชัน |
| `Validation.gs` | ตรวจความถูกต้องของเป้าหมาย ชุดบทบาท และการโหวต |
| `WinConditionService.gs` | เงื่อนไขชนะทุกฝ่าย รวมผู้ชนะเดี่ยว (Tanner / Hoodlum) |
| `EffectResolver.gs` | คิวการตายแบบลูกโซ่ การป้องกัน ทริกเกอร์เมื่อมีคนตาย และการสรุปผลกลางคืน |
| `RuleEngine.gs` | เครื่องยนต์กติกาทั้งหมด: สร้างเกม แจกบทบาท คืน วัน โหวต จบเกม |
| `GameService.gs` | สร้าง view model แยกระหว่างจอผู้ดำเนินเกมและจอสาธารณะ |
| `Storage.gs` | บันทึกลง Google Sheets, event log, snapshot สำหรับ Undo, lock, idempotency |
| `Auth.gs` | ตรวจ PIN ผู้ดำเนินเกมรายเกม |
| `SheetInitializer.gs` | สร้างชีตทั้งหมดและซิงก์ RoleCatalog |
| `Api.gs` | ฟังก์ชันทั้งหมดที่ฝั่งเว็บเรียกผ่าน `google.script.run` |
| `Code.gs` | `doGet` และเมนูในสเปรดชีต |
| `Index.html` / `CSS.html` / `JavaScript.html` | หน้าเว็บฝั่งผู้ใช้ |
| `appsscript.json` | manifest |
| `tests/` | ชุดทดสอบที่รันบน Node (ไม่ต้องอัปโหลดขึ้น GAS) |

## 2. ติดตั้งครั้งแรก

1. เปิด <https://script.google.com> → **New project**
2. เปิด **Project Settings** → ติ๊ก *Show "appsscript.json" manifest file in editor*
3. สร้างไฟล์ให้ตรงชื่อเดิมทุกไฟล์ แล้ววางเนื้อหาจากโฟลเดอร์นี้
   - ไฟล์ `.gs` → ชนิด *Script*
   - `Index.html`, `CSS.html`, `JavaScript.html` → ชนิด *HTML*
4. ผูกสเปรดชีต เลือกวิธีใดวิธีหนึ่ง
   - **วิธีอัตโนมัติ** — รันฟังก์ชัน `createSpreadsheetAndBind()` หนึ่งครั้ง
     ระบบจะสร้างสเปรดชีตใหม่ ตั้ง Script Property ให้ และสร้างชีตครบทุกแท็บ
   - **วิธีกำหนดเอง** — สร้างสเปรดชีตเอง คัดลอก ID จาก URL
     แล้วไปที่ **Project Settings → Script Properties → Add script property**
     - `SPREADSHEET_ID` = ไอดีของสเปรดชีต
     - `APP_SECRET` = ข้อความสุ่มยาว ๆ ที่คุณตั้งเอง
     จากนั้นรัน `setupSpreadsheet()`
5. รันฟังก์ชันครั้งแรกจะมีหน้าขออนุญาต ให้กด **Review permissions → Allow**

ชีตที่ถูกสร้าง: `Games`, `Players`, `Events`, `Snapshots`, `RoleCatalog`, `Settings`

## 3. ปรับค่า Village Impact ให้ตรงการ์ดจริง

ค่า `villageImpact` ของทั้ง 46 บทบาทในโค้ดเป็น **ค่าประมาณ** ไม่ได้คัดลอกจากตัวเลขบนการ์ดจริง
ให้เปิดชีต **RoleCatalog** แล้วแก้คอลัมน์ `villageImpact` ตามการ์ดในกล่องของคุณ
ระบบจะอ่านค่าจากชีตทับค่าในโค้ดอัตโนมัติทุกครั้งที่เรียก `loadCatalogOverrides()`

ในชีตเดียวกันยังปิด/เปิดบทบาทได้ที่คอลัมน์ `enabled` (เช่น ถ้ากล่องของคุณไม่มีชุดเสริมบางชุด)

## 4. Deploy เป็นเว็บแอป

1. **Deploy → New deployment → Web app**
2. ตั้งค่า
   - Execute as: **Me**
   - Who has access: **Anyone** (หรือ *Anyone with Google account* ถ้าต้องการจำกัด)
3. กด **Deploy** แล้วคัดลอก URL

**จอผู้ดำเนินเกม** — เปิด URL ตรง ๆ บนมือถือของผู้ดำเนินเกม

**จอสาธารณะ (ฉายขึ้นทีวี)** — เปิด URL เดิมแล้วต่อท้ายด้วย

```
?mode=public&g=GAME-XXXXXX
```

จอสาธารณะจะแสดงเฉพาะข้อมูลที่ผู้เล่นรู้ได้อยู่แล้ว (เฟส จำนวนคนที่ยังมีชีวิต ผู้เสียชีวิต ไทม์ไลน์)
และจะรีเฟรชอัตโนมัติทุก 5 วินาที **ไม่มีทางรั่วบทบาทลับ** เพราะใช้ view model คนละชุดกัน

### ทดสอบก่อนใช้จริง
ใช้ **Deploy → Test deployments** เพื่อลองโดยไม่กระทบ URL ที่แจกไปแล้ว

### ย้อนเวอร์ชัน (rollback)
**Deploy → Manage deployments → เลือก deployment → ไอคอนดินสอ → Version → เลือกเวอร์ชันเดิม → Deploy**
URL เดิมจะยังใช้ได้เหมือนเดิม ผู้เล่นไม่ต้องเปลี่ยนลิงก์

## 5. ขั้นตอนการใช้งานในเกมจริง

1. **สร้างเกม** — พิมพ์รายชื่อผู้เล่นตามลำดับที่นั่งจริง (บรรทัดละหนึ่งชื่อ)
   ระบบจะให้ `GAME-XXXXXX` และ **PIN ผู้ดำเนินเกม** ซึ่งแสดงครั้งเดียว ให้บันทึกไว้
2. **ผู้เล่น** — ปรับลำดับที่นั่งให้ตรงโต๊ะจริง (สำคัญกับ นักสืบเหนือธรรมชาติ มือระเบิดคลั่ง จ่าฝูงหมาป่า)
3. **บทบาท** — เลือกจำนวนการ์ดแต่ละใบให้เท่าจำนวนผู้เล่น ปรับตัวเลือกกติกา แล้วกดยืนยัน
   ระบบจะเตือนถ้าชุดบทบาทไม่สมเหตุสมผล
4. **แจกการ์ด** — สับและแจกการ์ด **จริง** ที่โต๊ะ จากนั้นบันทึกลงระบบว่าใครได้ใบไหน
   หน้าจอนี้เป็นความลับ ใช้ปุ่มรูปตาบนแถบบนเพื่อปิดจอทันทีเมื่อมีคนเดินผ่าน
5. **กลางคืน** — ระบบเรียงลำดับการปลุกให้เอง อ่านบทตามหน้าจอ เลือกเป้าหมาย แล้วกดบันทึก
   เมื่อครบทุกขั้นให้กด *สรุปผลกลางคืน*
6. **กลางวัน** — เดินผ่าน 4 ช่วงตามลำดับ
   *รุ่งเช้า* (ประกาศผล) → *อภิปราย* (นาฬิกาตัวที่หนึ่ง) → *เสนอชื่อ* (นาฬิกาตัวที่สอง)
   → *ลงคะแนน* แล้วกดสรุปผล  คนที่ถูกแม่มดชราส่งออกจะถูกล็อกไม่ให้เสนอชื่อโดยอัตโนมัติ
7. **จบเกม** — ระบบตรวจเงื่อนไขชนะให้อัตโนมัติ และแสดงตารางสรุปบทบาททุกคน

**ปุ่มย้อนกลับ** บนแถบบนจะย้อนไปยังสถานะก่อนคำสั่งสำคัญล่าสุด (เก็บ snapshot ไว้ 25 ชุดล่าสุด)

## 6. รันชุดทดสอบ

ชุดทดสอบรันบน Node ล้วน ไม่ต้องต่อ Google

```bash
cd tests
node run.js
```

ครอบคลุม unit tests ของฟังก์ชันหลัก และ scenario tests 30 สถานการณ์ตามสเปก
(คิวการตายลูกโซ่ ผู้คุ้มกัน แม่มด กามเทพ ดอพเพลแกงเกอร์ ลัทธิ แวมไพร์ คนบ้า อันธพาล ฯลฯ)

## 7. ตัวเลือกกติกาที่ปรับได้ (หน้า "เลือกบทบาท")

ทุกตัวในตารางนี้ **มีโค้ดรองรับจริงและมีชุดทดสอบคุมไว้แล้ว**

| ตัวเลือก | ค่าที่เลือกได้ | ผลในเกม |
|---|---|---|
| เปิดเผยบทบาทของผู้ที่ตาย | เต็ม / เฉพาะฝ่าย / ไม่เปิด | ควบคุมสิ่งที่จอสาธารณะแสดง |
| เมื่อคะแนนเสมอ | ไม่แขวน / ลงใหม่ / แขวนทุกคน / ผู้ดำเนินเกมตัดสิน | ผลการนับคะแนน |
| นายกเทศมนตรี | การ์ดบทบาท / เลือกตั้ง / ปิด | น้ำหนักคะแนนโหวต |
| ผู้หยั่งรู้ฝึกหัด | ตรวจคืนละคน / **คืนที่รับช่วงตรวจได้สองคน** | จำนวนเป้าหมายในคืนที่รับช่วง |
| กามเทพ | ใช้การ์ด / **ผู้ดำเนินเกมจับคู่เอง** | โหมดหลังเพิ่มขั้นตอนจับคู่ในคืนแรกโดยไม่ต้องมีการ์ด |
| ดอพเพลแกงเกอร์ | **เห็นการ์ดต้นแบบ** / **ไม่เห็นจนกว่าต้นแบบตาย** | ข้อความที่ผู้ดำเนินเกมอ่านให้ฟัง |
| แม่มด | ยาชุบชีวิต 1 + ยาพิษ 1 / **ใช้พลังได้ครั้งเดียวทั้งเกม** | โหมดหลังใช้ขวดใดขวดหนึ่งแล้วอีกขวดหมดไปด้วย |
| นักบวช | ให้พรคุ้มครองครั้งเดียว / **ตรวจบทบาทผู้ตายได้ทุกคืน** | โหมดหลังไม่มีพรคุ้มครอง และตื่นทุกคืนที่มีศพ |
| คนโง่ประจำหมู่บ้าน | รอดจากการแขวน / เสียสิทธิ์โหวตเท่านั้น | ผลเมื่อถูกแขวน |
| คนบ้าชนะเมื่อ | **ถูกโหวตแขวนคอ** / ตายด้วยวิธีใดก็ได้ | เงื่อนไขชนะส่วนบุคคล |
| คนบ้าชนะแล้วจบเกมทันที | เปิด / ปิด | เปิดอยู่เป็นค่าเริ่มต้น |
| แวมไพร์ | เปิด / ปิด | ปิดอยู่เป็นค่าเริ่มต้น |
| คนเมารู้ตัวในคืนที่ | 2–6 | คืนที่เปิดการ์ดจริงให้คนเมา |
| เวลาอภิปราย / เวลาเสนอชื่อ | วินาที | นาฬิกาสองตัวแยกกันในหน้ากลางวัน |
| **เวลาต่อขั้นตอนกลางคืน** | 0–180 วินาที | นาฬิกาเตือนในการ์ดขั้นตอน (0 = ปิด) |
| **หน่วงสุ่มตอนข้ามขั้นตอน** | 0–3000 มิลลิวินาที | หน่วงเวลาแบบสุ่มเมื่อกดข้าม เพื่อไม่ให้ผู้เล่นเดาจากความเงียบว่าขั้นนั้นไม่มีคนทำอะไร |

**ตัวเลือกที่ถูกถอดออก** เพราะจะกลายเป็นการแต่งกติกาขึ้นเอง มากกว่าจะสะท้อนกล่องจริง

- `minionMode` — เป็นการตัดสินใจตอนจัดสำรับ ไม่ใช่ตรรกะในเกม
  ถ้ากติกาบ้านให้หมาป่าเลือกสมุนภายหลัง ให้เอาการ์ดสมุนออกจากสำรับแล้วผู้ดำเนินเกมแตะไหล่แทน
- `cupidMode: TAKES_LEFTOVER_ROLE` — ระบบไม่ได้เก็บข้อมูลการ์ดที่เหลือในกล่อง จึงคำนวณให้ไม่ได้

## 7ก. เครื่องมือผู้ดำเนินเกม (ปุ่ม 🔧 บนแถบบน)

| คำสั่ง | ใช้เมื่อ |
|---|---|
| สลับบทบาทระหว่างผู้เล่นสองคน | บันทึกการ์ดสลับคนกัน |
| กลับไปแก้การแจกบทบาท | แจกผิดตั้งแต่ต้น (ล้างเหตุการณ์ทั้งหมดในเกม) |
| สั่งให้ผู้เล่นเสียชีวิต | มีเหตุนอกกติกา เช่น ผู้เล่นออกกลางคัน |
| ส่งออกตารางผู้เล่นลงชีต | อัปเดตแท็บ `Players` ให้ตรงสถานะปัจจุบัน (ปกติเขียนเฉพาะตอนจบเกม) |
| จบเกมทันที | ปิดเกมโดยไม่รอเงื่อนไขชนะ |

ทุกคำสั่งย้อนกลับได้ด้วยปุ่มย้อนคำสั่ง (↩️) บนแถบบน

## 7ข. หมายเหตุการตีความกติกา

ข้อเหล่านี้เป็นการตีความที่ฝังไว้ในโค้ด หากกล่องของคุณระบุต่างออกไป แก้ได้ที่ `Config.gs` หรือชีต `Settings`

- **จ่าฝูงหมาป่า (Big Bad Wolf)** — เหยื่อคนที่สองต้องนั่งติดกับเหยื่อคนแรก
  (ยกเว้นกรณีที่ลูกหมาป่าตายแล้วซึ่งให้เหยื่อเพิ่มอิสระ)
- **นายพราน (Hunter)** — ทริกเกอร์ยิงทำงานหลังคิวการตายว่างแล้ว ไม่ใช่ระหว่างคิว
  เพื่อไม่ให้เกิดลูปซ้อนกันเมื่อมีบทบาทเชื่อมโยงหลายชั้น
- **คนโง่ประจำหมู่บ้าน (Village Idiot)** — ค่าเริ่มต้นคือรอดจากการแขวนคอแต่หมดสิทธิ์โหวตตลอดเกม
- **คนบ้า (Tanner)** — ค่าเริ่มต้นชนะเมื่อถูกโหวตแขวนคอ และเกมจบทันทีที่ชนะ
- **แวมไพร์** — ปิดไว้เป็นค่าเริ่มต้น เปิดได้ที่ตัวเลือกกติกา `vampireEnabled`

## 8. หมายเหตุประสิทธิภาพ

Apps Script ตอบสนองต่อการเรียกหนึ่งครั้งราว 0.6–2 วินาทีเสมอ แก้ที่โค้ดไม่ได้
สิ่งที่ทำได้คือ **ลดจำนวนครั้งที่แตะ Google Sheets** ซึ่งวัดผลจริงด้วย Sheets จำลอง
ในชุดทดสอบ (`tests/mock-sheets.js` นับทุกการเรียก)

**คำสั่งธรรมดา 1 ครั้ง โต๊ะ 12 คน**

| ปฏิบัติการ | เดิม | ปัจจุบัน |
|---|---|---|
| `openById()` | 3 | **1** |
| `deleteRow()` ทีละแถว | 12 | **0** |
| อ่านคอลัมน์ทั้งคอลัมน์ | 4 | **1** |
| **รวมทุกการเรียก** | **28** | **8** |

**จอสาธารณะ 1 รอบ poll (ทุก 5 วินาที)**: จาก 9 การเรียก เหลือ 5

สาเหตุและวิธีแก้

1. **ตาราง `Players` เดิมถูกเขียนใหม่ทุกคำสั่ง** โดยลบแถวเก่าทีละแถว
   (`deleteRow` เป็นการเปลี่ยนโครงสร้างชีต ช้าที่สุดในบรรดาปฏิบัติการทั้งหมด)
   ทั้งที่ไม่มีโค้ดส่วนไหนอ่านตารางนี้เลย ตอนนี้เขียนเฉพาะตอนจบเกม
   กับตอนกดปุ่ม *ส่งออกตารางผู้เล่นลงชีต* ในเมนูเครื่องมือ และลบด้วย `deleteRows` ครั้งเดียว
2. **`openById()` ถูกเรียกซ้ำทุก helper** ตอนนี้จำ object สเปรดชีตและชีตไว้ตลอดการรัน
3. **จอสาธารณะอ่านชีต `RoleCatalog` ใหม่ทุก 5 วินาที** ตอนนี้ใช้แคช 6 ชั่วโมงร่วมกัน
   (กดปุ่ม *โหลดข้อมูลบทบาทจากชีตใหม่* เมื่อแก้ชีตแล้ว)
4. **เลขแถวของเกมถูกค้นหาซ้ำ 2–3 รอบต่อคำสั่ง** ตอนนี้จำไว้ใน CacheService
   และตรวจสอบกับชีตก่อนใช้ทุกครั้ง ถ้าไม่ตรงจะกลับไปค้นแบบเดิมเอง (มีเทสต์คุมกรณีนี้)

ฝั่งหน้าเว็บ

5. หน้าแจกบทบาทรวมการบันทึกเป็นครั้งเดียวหลังหยุดแก้ 1.2 วินาที
   จากเดิมยิงเซิร์ฟเวอร์ทุกครั้งที่เลือกดรอปดาวน์ (12 คน = 12 ครั้ง)
6. ข้อมูลบทบาท 46 ใบแคชไว้ในเบราว์เซอร์ เปิดแอปครั้งที่สองเห็นหน้าจอทันที
7. ช่องค้นหาบทบาทหน่วง 180 มิลลิวินาทีก่อนวาดใหม่

**ยังไม่ได้ทำ (ระยะที่ 3)** — `withGameLock` ใช้ล็อกระดับทั้งสคริปต์
ถ้าเปิดเล่นพร้อมกันสองโต๊ะ สองโต๊ะจะรอกันเองแม้เป็นคนละเกม
แก้ได้แต่ต้องเขียน mutex ต่อเกมเอง ซึ่งเสี่ยงกว่าเดิม จึงคงไว้แบบปลอดภัยก่อน

## 9. สิ่งที่ควรยืนยันกับกล่องเกมของคุณ

1. กล่องของคุณมีชุดเสริมใดบ้าง (Wolfpack / Hunting Party / ทั้งสอง)
2. สมุนหมาป่า — แจกเป็นการ์ด หรือให้หมาป่าเลือกภายหลัง (ตัดสินใจตอนจัดสำรับ ไม่มีสวิตช์ในแอป)
3. เปิดเผยบทบาทของผู้ที่ตายหรือไม่ (เต็ม / เฉพาะฝ่าย / ไม่เปิด)
4. คะแนนเสมอแล้วทำอย่างไร (ไม่แขวน / โหวตใหม่ / แขวนทุกคน / ผู้ดำเนินเกมตัดสิน)
5. แวมไพร์เล่นร่วมกับหมาป่า หรือเล่นแทนหมาป่า
6. แม่มดใช้ยาได้สองขวดในเกม หรือใช้พลังได้ครั้งเดียว
7. ตัวเลข Village Impact บนการ์ดจริงของแต่ละบทบาท
