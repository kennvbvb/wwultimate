# Ultimate Werewolf — Moderator Console

เว็บแอปช่วย **ผู้ดำเนินเกม (Moderator)** ดำเนินเกมกระดาน *Ultimate Werewolf: Deluxe Edition*
สำหรับการเล่นแบบเจอหน้ากันโดยใช้การ์ดจริง

แอปทำหน้าที่เป็น “สมองและสมุดจด” ของผู้ดำเนินเกม — จำว่าใครเป็นอะไร คำนวณผลกลางคืน
จัดลำดับการปลุก นับคะแนน ตัดสินผู้ชนะ **ไม่ได้แทนการ์ด และไม่แสดงภาพหรือข้อความจากการ์ดจริง**

- ผู้ใช้จริง: ครูโรงเรียนประถม ใช้กับนักเรียน เปิดบนมือถือเป็นหลัก
- อินเทอร์เฟซและข้อความทั้งหมดเป็นภาษาไทย
- บทบาทครบ 46 ตัว (Core 34 / Wolfpack 6 / Hunting Party 6) และตัวเลือกกติกา 18 ตัว

## สแตกที่ใช้

| ส่วน | เทคโนโลยี |
|---|---|
| เฟรมเวิร์ก | Next.js 15 (App Router) + React 19 + TypeScript |
| ฐานข้อมูล | Postgres (Neon บน Vercel) — เก็บ state เป็น `jsonb` |

| โฮสต์ | Vercel |
| ตรรกะเกม | ไฟล์ `.gs` เดิม 8 ไฟล์ ต่อเป็น ES module ตอน build (ไม่แก้ตรรกะแม้แต่บรรทัดเดียว) |

## จอที่มี

| จอ | URL | ต้องล็อกอิน |
|---|---|---|
| ผู้ดำเนินเกม | `/` | ต้องมี PIN ของเกม (ครั้งเดียวต่ออุปกรณ์) |

## ติดตั้งเพื่อพัฒนา

```bash
npm install
cp .env.example .env.local     # แล้วเติมค่าจริง
npm run db:migrate             # สร้างตารางใน DATABASE_URL
npm run dev                    # http://localhost:3000
```

ต้องมี Node 22.6 ขึ้นไป (ชั้นเทสต์รันไฟล์ `.ts` ด้วย Node ตรง ๆ) — ประกาศไว้ใน `engines` ของ
`package.json` แล้ว Vercel จึงเลือกเวอร์ชันให้เอง

### ตัวแปรสภาพแวดล้อม

| ชื่อ | จำเป็น | ใช้ทำอะไร |
|---|---|---|
| `DATABASE_URL` | ✅ | connection string ของ Postgres |
| `AUTH_SECRET` | ✅ (production) | กุญแจเซ็น cookie ผู้ดำเนินเกม ยาวอย่างน้อย 16 ตัวอักษร |
| `ADMIN_PASSWORD` | ✅ (ถ้าจะใช้ `/admin`) | รหัสผ่านหน้าแก้บทบาท คนละตัวกับ PIN ของเกม |
| `VILLAGE_IMPACT_VERIFIED` | — | ตั้งเป็น `true` เมื่อแก้ค่า Village Impact ให้ตรงการ์ดจริงครบแล้ว คำเตือนจะหายไป |
| `RATE_LIMIT_CREATE_GAME` | — | จำนวนเกมที่สร้างได้ต่อ IP ต่อชั่วโมง (ค่าเริ่มต้น 30) |
| `RATE_LIMIT_MODERATOR_LOGIN` | — | จำนวนครั้งที่กรอก PIN ได้ต่อ 10 นาที (ค่าเริ่มต้น 10) |
| `RATE_LIMIT_ADMIN_LOGIN` | — | จำนวนครั้งที่กรอกรหัสผ่านแอดมินได้ต่อ 10 นาที (ค่าเริ่มต้น 10) |
| `DB_POOL_MAX` | — | ขนาด pool ต่อ instance (ค่าเริ่มต้น 3) |

**ห้าม commit** `.env.local` หรือ connection string ใด ๆ

## deploy บน Vercel

1. Vercel → New Project → เลือก repo นี้
2. Storage → Create → **Neon Postgres** → เชื่อมกับโปรเจกต์ (Vercel ใส่ `DATABASE_URL` ให้เอง)
3. Settings → Environment Variables → ใส่ `AUTH_SECRET` และ `ADMIN_PASSWORD`
4. รัน migration หนึ่งครั้ง (รายละเอียดเต็มอยู่ที่ [วิธีรัน migration แบบละเอียด](#วิธีรัน-migration-แบบละเอียด)):
   ```bash
   vercel env pull .env.local
   npm run db:migrate
   ```
5. Deploy — Build Command ใช้ค่าเริ่มต้น `npm run build` (สำคัญ: มันจะสร้าง
   `lib/engine.generated.js` ให้ก่อน ถ้าตั้งเป็น `next build` ตรง ๆ จะ build ไม่ผ่าน)

`npm run build` จะสร้าง `lib/engine.generated.js` ให้อัตโนมัติผ่าน `prebuild`

### ตรวจหลัง deploy

```bash
npm run verify:deploy https://ที่อยู่ของเว็บ
```

ตรวจแบบอ่านอย่างเดียว 14 ข้อ (ไม่สร้าง ไม่แก้ ไม่ลบอะไรเลย จึงยิงใส่ production ได้):
เว็บขึ้นไหม ต่อฐานข้อมูลได้ไหม migration ครบไหม บทบาทครบ 46 ไหม
endpoint ที่ต้องมีรหัสผ่านปิดอยู่จริงไหม security headers ติดไหม และ SSE เปิดได้ไหม

### หลัง deploy ควรตั้งค่าเพิ่ม

- ชี้ uptime monitor ไปที่ `/api/health` (คืน 503 เมื่อต่อฐานข้อมูลไม่ได้ หรือเมื่อยังรัน migration ไม่ครบ)
  ตัวอย่างคำตอบ: `{"ok":true,"db":"up","schema":"ok","appVersion":"2.0.0","engineVersion":"1.0.0"}`
  ถ้าได้ `"schema":"outdated"` แปลว่าโค้ดใหม่ขึ้นไปแล้วแต่ฐานข้อมูลยังตามไม่ทัน — รัน `npm run db:migrate`
- เข้า `/admin` เดือนละครั้งเพื่อกด **ล้างข้อมูลที่หมดอายุ** และลบเกมเก่าที่ไม่ต้องใช้แล้ว
  (ระบบเก็บชื่อนักเรียนไว้ จึงไม่ควรเก็บนานเกินจำเป็น)
- เปิด Point-in-time restore ของ Neon แล้วลองกู้ข้อมูลจริงหนึ่งครั้งก่อนใช้สอน

### วิธีรัน migration แบบละเอียด

migration คือไฟล์ `.sql` ใน `migrations/` ที่สร้างตารางและคอลัมน์ให้ฐานข้อมูล
รันจาก**เครื่องของคุณ** ชี้ไปที่ฐานข้อมูลของ production — Vercel ไม่รันให้เองตอน deploy

รันซ้ำได้ปลอดภัยเสมอ ไฟล์ที่รันไปแล้วจะถูกข้าม

#### วิธีที่ 1 — ดึงค่าจาก Vercel (แนะนำ)

```bash
npm i -g vercel          # ครั้งเดียวพอ
vercel login             # เปิดเบราว์เซอร์ให้ยืนยันตัวตน
cd /path/to/wwultimate   # โฟลเดอร์โปรเจกต์
vercel link              # ครั้งแรกเท่านั้น — เลือกโปรเจกต์บน Vercel ให้ตรง
vercel env pull .env.local
npm run db:migrate
```

`vercel env pull` จะเขียนไฟล์ `.env.local` ที่มี `DATABASE_URL` ของจริง
(`.env.local` อยู่ใน `.gitignore` แล้ว จึงไม่ถูก commit)
`npm run db:migrate` อ่านไฟล์นี้ให้เอง ไม่ต้องตั้งค่าอะไรเพิ่ม

#### วิธีที่ 2 — ใส่ค่าเชื่อมต่อตรง ๆ (ไม่ต้องลง Vercel CLI)

คัดลอกค่า `DATABASE_URL` จาก Vercel → โปรเจกต์ → **Storage** → เลือกฐานข้อมูล → **.env.local**
(หรือจาก Neon → **Connection string**) แล้ว

```bash
DATABASE_URL="postgres://user:pass@host/db?sslmode=require" npm run db:migrate
```

ใส่เครื่องหมายคำพูดครอบเสมอ เพราะค่ามักมีอักขระพิเศษ

#### ผลลัพธ์ที่ควรเห็น

```
ฐานข้อมูลปลายทาง: postgres://***@ep-xxxx.neon.tech/neondb
ใช้ migration แล้ว: 003_retention.sql
เสร็จสิ้น 1 migration
```

ถ้าฐานข้อมูลอัปเดตอยู่แล้วจะขึ้นว่า `ฐานข้อมูลเป็นเวอร์ชันล่าสุดอยู่แล้ว` — ถือว่าปกติ

#### ตรวจว่าสำเร็จจริง

```bash
curl -s https://ที่อยู่เว็บของคุณ/api/health
```

ต้องได้ `"schema":"ok"` แล้วเปิดเว็บสร้างเกมทดสอบหนึ่งเกม

#### ปัญหาที่พบบ่อย

| ข้อความ | แปลว่า | แก้อย่างไร |
|---|---|---|
| `ไม่พบ DATABASE_URL` | ยังไม่มี `.env.local` หรืออยู่ผิดโฟลเดอร์ | `cd` ให้ถูกโฟลเดอร์ แล้ว `vercel env pull .env.local` ใหม่ |
| `ต่อฐานข้อมูลไม่ได้` | ค่าเชื่อมต่อผิด หรือคัดลอกมาไม่ครบ | คัดลอก `DATABASE_URL` ใหม่ทั้งบรรทัด รวม `?sslmode=require` |
| `self-signed certificate` | ค่าที่ใช้ไม่ใช่ของ Neon/Vercel | ใช้ค่าจาก Vercel เท่านั้น อย่าปิดการตรวจใบรับรอง |
| เว็บยังขึ้น error เหมือนเดิม | รัน migration ใส่คนละฐานข้อมูล | ดูบรรทัด `ฐานข้อมูลปลายทาง:` ว่าตรงกับของ production หรือไม่ |

### migration ใหม่

วางไฟล์ `.sql` ใน `migrations/` ตั้งชื่อขึ้นต้นด้วยเลขลำดับ แล้วรัน `npm run db:migrate`
ไฟล์ที่รันไปแล้วถูกบันทึกไว้ในตาราง `schema_migrations` จึงรันซ้ำได้ปลอดภัย
แล้วเพิ่มแถวใน `REQUIRED` ของ `lib/schema.ts` ด้วย เพื่อให้ `/api/health` รู้จักตาราง/คอลัมน์ใหม่


**ลำดับตอนอัปเดตของจริง: รัน migration ก่อน แล้วค่อย deploy โค้ดใหม่**
migration ทุกไฟล์ในโปรเจกต์นี้เป็นแบบเพิ่มอย่างเดียว (เพิ่มตาราง/คอลัมน์) โค้ดเวอร์ชันเก่า
จึงยังทำงานได้ระหว่างรอ deploy แต่โค้ดใหม่ทำงานไม่ได้ถ้ายังไม่ได้รัน migration

## วิธีใช้งานในห้องเรียน

1. เปิดหน้าแรก ใส่ชื่อผู้เล่นเรียงตามที่นั่งจริง แล้วกดสร้างเกม
2. **จด PIN ที่ขึ้นมาครั้งเดียว** ใช้ตอนเปิดเกมเดิมจากอุปกรณ์อื่น
3. เลือกชุดบทบาท (กด “จัดชุดแนะนำอัตโนมัติ” ได้) แล้วยืนยัน
4. แจกการ์ดจริงให้ผู้เล่น แล้วบันทึกในหน้า “แจกการ์ด” ว่าใครได้ใบไหน
5. กดเริ่มคืนแรก แล้วทำตามบทที่ขึ้นบนจอทีละขั้น — ระบบจะเด้งคำตอบของแต่ละบทบาท
   (เช่น ผู้หยั่งรู้ให้พยักหน้าหรือส่ายหน้า) ผลของกลางคืน และผลการแขวนคอ ให้กดรับทราบทีละอัน
6. เปิดจอสาธารณะบนทีวีด้วยการ **สแกน QR** ที่ขึ้นตอนสร้างเกม (หรือกดเมนู 🔧 → เปิดจอสาธารณะ)
   ไม่ต้องพิมพ์รหัสเกมด้วยรีโมท
7. ถ้าลืมรหัสเกม เปิด `/admin` (ต้องใช้รหัสผ่านผู้ดูแล) เพื่อดูรายการเกมที่ยังเล่นค้างอยู่
8. หลังเล่นจบหลายเกม ดูภาพรวมได้ที่ `/admin/stats` — อัตราชนะแยกฝ่าย บทบาทที่ใช้บ่อย
   และสถิติรายคน (จับคู่ตามชื่อที่พิมพ์ไว้)

ปุ่มที่ใช้บ่อยที่สุดคือ **👁️ ซ่อนจอ** ที่มุมบนขวา — กดแล้วจอดำทันทีเมื่อมีคนเดินผ่าน
ถัดมาคือ **↩️ ย้อนกลับหนึ่งขั้น** ใช้เมื่อแตะเป้าหมายผิดคนกลางคืน และ **🔔** สำหรับเปิด/ปิดเสียงเตือนนาฬิกา
